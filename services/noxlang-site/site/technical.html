Technical specifications

What Nox is, precisely.

The facts behind the language, in one place: how it compiles, how memory and errors work, where it runs, how big the binaries are and what ships in the box. Current release: Nox {{VERSION}}. Every row links to the page that documents it.

Language

Python’s syntax, a static type system.

TypingStatic and mandatory: every parameter, variable and return value has a type the compiler checks. There is no Any and no implicit dynamic fallback, not even inside lowlevel. See the language guide.
Generics and protocolsCompile-time monomorphization with structural protocols; a heterogeneous collection falls back to a fat pointer without any change in the source.
ErrorsExceptions compile to an implicit error-union return chain. No unwind tables and no landing pads are emitted, on either back end.
Concurrencyasync/await, tasks and channels on an M:N work-stealing scheduler. Multi-core parallelism is a property of the LLVM back end; QBE programs run tasks on one thread.

Memory

Managed without a vocabulary.

Layer 1 · ASAPA value is freed at its last use when the compiler can prove it is safe. No reference count, no cost at run time.
Layer 2 · ARCWhen that cannot be proved the value is reference-counted, silently. It is never a compile error and never a hint you must write.
Layer 3 · cycle collectorScans only ARC-managed objects, triggered by allocation pressure.
Layer 4 · lowlevelArena, pool and raw-pointer allocation. It relaxes how memory is allocated, never how types are checked. See ownership.

Interop

Three APIs, one stability promise.

NNIA stable C ABI with opaque, generation-checked handles. Native code never sees a pointer into Nox’s heap. Read more.
Plugin APIA manifest and lifecycle for native plugins loaded at run time with declared capabilities. Read more.
NAPIThe language surface and standard library that frameworks program against. Read more.
extern defDirect C calls, with noxc bindgen generating bindings. This runs with full native authority; see security.
Embedded WebAssemblyImport a .wasm module as a library through the embedded interpreter.

Toolchain

One command for everything.

noxcinit, build, run (with an optional OS sandbox), check, test, fmt, explain, bindgen, package commands (add, search, publish, install), lockfile signing and SBOM output, and upgrade for the compiler itself. Reference.
EditorsA language server (noxlsp), a VS Code extension and a tree-sitter grammar.
PackagesThe noxpkg registry with GitHub sign-in; each package carries a source label (Nox, C, C++, Rust, Go, Zig or mixed).
To build programsA C toolchain for linking; clang or zig for the LLVM back end. To build the compiler from source: Zig 0.16.
