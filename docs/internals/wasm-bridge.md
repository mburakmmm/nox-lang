# WebAssembly bridge

WASM as a *library import* is separate from WASM as a *compilation target*. Importing a module goes through the embedded interpreter; compiling Nox itself to WebAssembly is `--target wasm32-wasi` ([WebAssembly](../tools/wasm.md)). `runtime/wasm_bridge/` holds the parser and the runtime glue.

**Interpreter coverage (2.1.65).** The embedded WebAssembly engine is a pure-Zig validator and interpreter (no JIT, no third-party code, so it also runs on iOS and Android). It decodes every section of the WebAssembly 2.0 core except SIMD and threads, validates each function with the specification's typing algorithm before running anything, and executes `i32`/`i64`/`f32`/`f64` arithmetic and conversions, multi-value blocks and returns, linear memory, globals, tables with `call_indirect`, reference types, bulk-memory and sign-extension/saturating instructions. Modules are untrusted: memory and table accesses are bounds-checked, and instances carry limits for fuel (each branch and call costs one), value-stack and call depth, and memory pages. Correctness is checked bit-for-bit against V8 (`scripts/wasm_gen_vectors.py`) and against real compiler output (`scripts/wasm_gen_programs.py`). The current Nox surface is still the single built-in `wasm_call(path, name, arg)`; a persistent instance handle, host functions and WASI are tracked separately.
